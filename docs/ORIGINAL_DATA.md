# Цель: файлы с GitHub + оригинальная Steam-копия

## Обновление после проверки открытых проектов

Предпочтительный путь теперь — **Butterscotch с уже существующим Switch-бэкендом**, а не
новый хук закрытого рантайма. Оригинальный Steam-файл получен и успешно прошёл начальный
headless-тест в этом открытом движке без конвертации (титул и вход в обучение).
Это ещё не проверка полноценного игрового процесса/изображения/звука на Switch.
[Результаты и воспроизводимая сборка](../open-runner/README.md),
[сравнение движков](OPEN_RUNNER_RESEARCH.md).

Ниже сохранён технический план для **прежнего закрытого рантайма**, как альтернативный путь;
он больше не является единственным рассматриваемым способом.

## Желаемый сценарий

1. Скачать только компоненты, которые проект имеет право распространять.
2. Скопировать исходный `data.win`, аудиогруппы и Included Files из своей Steam-установки.
3. Запустить совместимое приложение на Switch. Никакого PC-конвертера и никакого нового
   `data.win`/`game.win` на SD; исходники остаются неизменными.

**Это цель разработки, а не уже готовая возможность.** В текущих инструментах конвертация
остаётся локальным PC-шагом. Патч выхода сам по себе поддержку старого формата не добавляет.

## Что дала история чата

История, добавленная владельцем в рабочую ветку 8 сентября 2026 года, описывает несколько
ошибочных промежуточных сборок. Выводы из неё сверены с существующими скриптами и локальной
ранее преобразованной копией данных. Старые обещания из чата не считаются тестами или лицензией.

Для Санаэ подтверждены следующие задачи совместимости:

| Различие | Что нужно перенести в загрузчик |
|---|---|
| ROOM до 2024.13 | Дополнительное поле порядка создания инстансов, правильное размещение последующих полей |
| Create-события | Порядок из реальных instance IDs, а не пустой список; соответствующий уровень флагов комнат |
| AGRP до 2024.14 | Пути внешних аудиогрупп, без чтения чужого поля как указателя/NULL |
| Steam API на Switch | Эквивалент текущей адаптации пяти call sites; сохранить цепочки ссылок FUNC |
| Имя входного файла | Явное чтение `data.win`, не скрытый выбор оставшегося старого `game.win` |
| Внешние файлы | Оригинальные аудиогруппы и CSV рядом с данными, не внутри `data.win` |

`scenario_sanae.csv` и `scenario_sanae_en.csv` обязательны для диалогов. Их отсутствие ранее
вызывало `load_csv -> -1` и ошибку `ds_grid_width`. Их копирование и проверка добавлены в
текущий PC-подготовщик. Пустые аудиогруппы 1 и 18 не требуют несуществующих архивов.
Если в оригинальной папке есть `scenaorio_sanae.csv` или `item.txt`, они также копируются.

## Предпочтительный технический путь: адаптация в RAM

Не патчить десятки чтений структуры по одному, а перехватить **буфер данных до начала
разбора чанков и преобразования файловых смещений в адреса памяти**:

1. Прочитать оригинал и проверить поддерживаемую версию/структуру.
2. Выделить новый буфер в памяти с проверками переполнений и отказа выделения.
3. Воспроизвести минимальные необходимые преобразования ROOM/AGRP и Steam-call-site адаптацию
   на этом буфере, не меняя исходный файл. Обновить FORM и размер последнего чанка.
4. Передать рантайму новый указатель **и корректный размер**, сохранив ожидаемое владение памятью.
5. Сохранить буфер на весь необходимый рантайму срок; корректно освободить/заменить его при
   выходе и `game_restart`, не допуская двойного преобразования или двойного освобождения.

Это всё ещё преобразование данных, но только временного представления в оперативной памяти.
Новый файл на диске не создаётся. Python-скрипт нельзя просто положить в ExeFS и ожидать его
исполнения: нужен нативный AArch64-компонент/хук загрузчика, собранный из разрешённого исходного кода.

Альтернатива — научить каждый нужный парсер читать старую структуру напрямую. Это может убрать
дополнительный буфер, но требует более широкого вмешательства в рантайм. Пока ни один вариант
не интегрирован и не проверен на Switch.

## Проверки перед обещанием «скопировал и работает»

- Найти точную точку перехвата в рантайме 2024.14.3.260, порядок чтения/разбора и правила владения буфером.
- Проверить нативный адаптер на **оригинальном, не преобразованном** Steam `data.win`.
  Теперь он получен в приватные локальные входы; SHA-256 приведён в open-runner/README.md.
  Нативный адаптер для старого закрытого рантайма всё ещё не реализован.
- Сопоставить результат в памяти с эталонным результатом существующих скриптов; проверить
  указатели, 104 комнаты, реальные Create-события, аудио и цепочки ссылок VM.
- На консоли проверить запуск, оба языка/диалоги, обучение, переход после мини-босса, сохранения,
  возврат в титул, выход, повторный запуск, Pro Controller и Joy-Con.
- Подтвердить, что исходный `data.win` на SD не изменился и новый файл данных не появился.
- Отказаться от запуска с понятной диагностикой при неподдерживаемой версии, без угадывания формата.

## Отдельный вопрос: право распространять исполняемую часть

Отсутствие игровых ассетов в NSP **не означает**, что находящийся внутри закрытый GameMaker/Nintendo
runtime разрешено распространять. Его переименование, перепаковка или размещение в ZIP этого
не меняет. Старое утверждение об обратном в истории чата было необоснованным.

Предыдущий рабочий ZIP выхода содержал полный изменённый `main`. Это не пример маленького
независимого патча и не подтверждение прав на публикацию рантайма.

Маленький самостоятельно написанный патч может не содержать ни игры, ни полного рантайма,
но он требует уже имеющийся базовый исполняемый компонент. Владение Steam-копией автоматически
такой компонент и права на него не предоставляет.

Чтобы **новому пользователю только со Steam-копией** действительно хватало GitHub + своих файлов,
нужен один из путей:

- Согласованный с правообладателями выпуск разрешённой к распространению Switch-сборки/рантайма.
- Независимый совместимый движок с подходящей лицензией. Это отдельный большой проект,
  а не продолжение небольшого патча выхода.

Техническая адаптация в памяти решает вопрос `data.win`, но не заменяет разрешения на рантайм.
Наличие публичной ссылки на бинарник или отсутствие в нём игровых текстур — не проверка лицензии.
